社内ナレッジ循環基盤｜Enterprise Knowledge Cycle Platform

人 × AIで知見を標準化する
循環型ナレッジ基盤

日々の業務で生まれる経験・判断・失敗・工夫・技術的な気づきを、AIが統合・構造化し、人がレビュー・承認。現場知を「会社の標準知」に育て、再利用と効果検証まで循環させる。

1. 企画概要

本企画は、資料を蓄積するだけの文書庫ではなく、現場の経験を会社の標準知へ昇格させ、再利用し、その効果まで検証する仕組みを構築するものです。

基本思想は、AIに正解を決めさせることではありません。AIは大量情報の整理・比較・候補化・レビュー支援を担い、技術的な確定判断と正式な標準化は人が責任を持ちます。

3. 各工程の役割

工程主担当主な処理成果物
記録人間日報、設計検討、施工上の工夫、トラブル、改善案、会議、写真・図面・文書を登録一次情報

構造化AI案件、工種、設備、原因、対策、条件、適用範囲、根拠、成果などを抽出構造化ナレッジ
知見候補化AI重複統合、類似事例検索、成功・失敗条件を整理知見候補
技術レビュー支援AI根拠資料提示、類似事例比較、矛盾・不足・旧版基準を警告レビュー資料
レビュー・承認人間技術的妥当性、適用範囲、例外条件、表現を確認承認済み知見
仕様・標準へ反映人間＋AI標準書、チェックリスト、教育資料、設計・施工手順の改訂案を作成標準・仕様案
効果検証・再学習AI＋人間利用状況、再発率、時間削減、品質改善を評価改善評価・次期学習材料

4. AIと人間の責任分界

AIが担当する領域

  • 大量データの検索・統合
  • 文書・会話・帳票からの項目抽出
  • タグ付け、分類、類似度判定
  • 重複・矛盾・不足情報の検出
  • 知見候補のドラフト生成
  • 適用条件・例外条件・根拠資料の候補提示
  • 過去事例・基準類との照合
  • レビュー観点・チェック項目の提示
  • 利用実績・効果指標の集計

人間が責任を持つ領域

  • 一次情報の事実性
  • 技術判断の確定
  • 適用可能範囲の決定
  • 例外条件の判断
  • 標準化するか否かの承認
  • 公式仕様・標準の発行
  • AI出力に対する最終責任

6. 検索・活用イメージ

利用者は単純な全文検索だけではなく、自然言語で質問します。AIは回答だけでなく、承認済みナレッジ・元資料・適用条件・例外条件を併記します。

「港湾工事でコンクリート打設時に過去発生した不具合と対策を教えて」
「この仮設計画に似た過去案件と注意点を出して」
「この設計条件で見落としやすい確認事項を一覧化して」

8. 承認ワークフロー

  1. 現場・技術者が情報を登録
  2. AIが既存情報と統合し構造化
  3. AIが「知見候補」を生成
  4. AIが根拠資料・類似事例・不足情報を提示
  5. 技術担当者がレビュー
  6. 必要に応じて専門分野責任者へエスカレーション
  7. 承認されたものだけを「社内公式ナレッジ」に昇格
  8. 標準化対象は別途、標準改訂承認を実施
  9. 発行後、利用実績と効果を追跡

9. AI品質・ガバナンス設計

  • AI回答には必ず根拠情報を紐付ける
  • 出典不明の内容は正式知見へ昇格させない
  • 未確認情報と承認済み情報をUI上で明確に区別
  • 基準・仕様の版数を管理
  • 条件変更時は過去承認の再確認を要求
  • AIが不明条件を無断補完しない
  • 重要判断はHuman-in-the-loopを必須化
  • 閲覧・編集・承認権限を役割別に設定
  • 個人・機密情報は権限・マスキング・保持期間を管理
  • 誰が・いつ・何を根拠に承認したか監査可能にする

10. PoC案

最初から全社を対象にせず、1テーマ・1部門・限定データで「知識循環が実際に回るか」を検証します。

候補A

設計照査・設計検討ノウハウ

候補B

仮設計画・施工計画の過去事例

候補C

品質不具合と再発防止

候補D

現場改善・省力化事例

候補E

技術問い合わせと回答履歴

候補F

2年次教育など技術教育Q&A

PoCの対象範囲は「情報収集 → AI構造化 → 知見候補 → 人レビュー → 検索利用」まで。標準改訂の自動化は第2段階とします。

11. PoC評価指標

登録登録件数・登録者数・情報欠落率
検索回答到達時間・検索成功率・再検索率
AI品質分類精度・根拠提示率・誤情報率
レビュー1件あたりレビュー時間・差戻し率
再利用参照回数・類似案件への再利用率
業務効果資料作成・問い合わせ・手戻り削減
品質同種不具合再発率・標準逸脱件数
学習利用者評価・採用／却下理由の蓄積率

12. 導入ロードマップ

Phase 1｜PoC限定テーマで収集・構造化・検索・レビューを検証。
Phase 2｜技術部門展開複数分野へ拡張し、承認済み知見DBとレビュー運用を整備。
Phase 3｜標準・仕様連携社内標準・チェックリスト・教育資料の改訂候補をAI生成。
Phase 4｜全社循環設計・施工・品質・安全・DX・教育を横断し、継続的に知見を更新。

13. 本企画のポイント

  • 「AIに全部任せる」設計ではない
  • AIは知識整理・比較・候補化・レビュー支援に集中
  • 公式知見への昇格は人間の承認を必須化
  • 元資料と判断結果を常に追跡可能にする
  • 利用・評価結果を次の知見へ戻し、継続改善する
  • 経験豊富な技術者の暗黙知を、次世代が再利用できる形へ変える

14. 期待効果

  • ベテラン技術者への問い合わせ集中を軽減
  • 過去資料を探す時間を削減
  • 同じ失敗・検討の繰り返しを削減
  • 技術レビュー品質を底上げ
  • 設計・施工ノウハウの属人化を緩和
  • 若手教育を高度化
  • 社内標準の更新サイクルを短縮
  • 「記録しただけ」で終わらない知識循環を実現

15. 次の検討事項

  • PoC対象テーマの決定
  • 利用部門・レビュー責任者の決定
  • 既存データの所在とアクセス権整理
  • 承認レベル・責任分界の定義
  • AI利用可能データと機密区分の整理
  • 既存Slack・CDE・文書管理基盤との連携方針
  • PoCのKPIと合格基準の設定
まずは完璧な全社システムを狙わない。 小さなテーマで知識循環が回るかを確かめ、AIを「100点の先生」ではなく「優秀な整理役・レビュー補助役」として育てていく。
